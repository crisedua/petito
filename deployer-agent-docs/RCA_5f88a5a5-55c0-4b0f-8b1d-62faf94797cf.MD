# RCA — Petito Plus (Mercado Pago) not charging on petito.pro

## Problem statement
`GET https://petito.pro/api/config` returns `payment_mode: demo` and `free_mode: true`. App code only enables real Mercado Pago charging when `PAYMENT_MODE=mercadopago` AND `MERCADOPAGO_ACCESS_TOKEN` is present, and only enforces the paywall when `FREE_MODE=false`. So production is in demo/free mode and NOT charging.

## Verification performed
- Live probe: `GET https://cuentapatas-demo.emergent.host/api/config` → 200, body contains `"payment_mode":"demo"`, `"free_mode":true`. Confirms the reported symptom.
- Redeploy status: latest run `5f88a5a5-55c0-4b0f-8b1d-62faf94797cf` (type=redeploy) status=success, completed 2026-10-15T12:04:40Z, and is the active run serving traffic. **The redeploy DID complete and the latest code is live.** The gap is purely production secret configuration, not a stale deploy.
- Secret store inspection (`list_secrets`, metadata_available=true, active/live run — values never revealed):

| Secret | Exists | State | Expected | Result |
|---|---|---|---|---|
| `FREE_MODE` | yes | not empty | equals "false" | **matches_expected=FALSE** → value is NOT "false" |
| `PAYMENT_MODE` | yes | not empty | equals "mercadopago" | **matches_expected=FALSE** → value is NOT "mercadopago" |
| `MERCADOPAGO_ACCESS_TOKEN` | yes | **is_empty=TRUE (blank)** | starts with "APP_USR-" | blank — prefix cannot be satisfied |
| `MERCADOPAGO_WEBHOOK_SECRET` | yes | **is_empty=TRUE (blank)** | present (optional) | blank |

## Root cause
All four production secrets are misconfigured in the production Secrets store:
1. `FREE_MODE` does not equal "false" (free paywall-off mode stays on → `free_mode:true`).
2. `PAYMENT_MODE` does not equal "mercadopago" (stays demo → `payment_mode:demo`).
3. `MERCADOPAGO_ACCESS_TOKEN` is blank (empty).
4. `MERCADOPAGO_WEBHOOK_SECRET` is blank (empty, optional).

Each of the three required gates the code checks is failing, so the backend correctly reports demo + free. These are USER-owned custom secrets carried forward from the previous production run (and edited in the Secrets tab win over preview), so the preview values never overwrote them.

## Fix (user action — I cannot set secret values)
In Deployment Panel → Secrets for `cuentapatas-demo`, set the production values and redeploy:
- `FREE_MODE` = `false`
- `PAYMENT_MODE` = `mercadopago`
- `MERCADOPAGO_ACCESS_TOKEN` = the production token (must start with `APP_USR-`, not `TEST-`)
- `MERCADOPAGO_WEBHOOK_SECRET` = production webhook secret (optional)

Then redeploy and re-verify `GET /api/config` shows `payment_mode: mercadopago` and `free_mode: false`.
